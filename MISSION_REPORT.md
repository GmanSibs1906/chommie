Generated made-up exercise-book photos for learners 6B-001 to 6B-007 (`demo/books/`).

Evidence `.albert/build-checks/snap/`.
- Not tested: a real camera stream, torch and the iOS path (headless Chrome has no camera). Needs the pilot's low-end Android test. The "send now" override and Wi-Fi hold are applied when the Mark screen uploads (next feature).
- Fixed: `hidden` attribute was overridden by button display; added a global `[hidden]` rule.

## 6. Marking + Reviewer + Marking review — ✅ passing (R9, R18, R19, R20, R25, R29, R33)
- Done: `/api/mark` (one request per learner, all pages as "Image 1:", "Image 2:" placed BEFORE the memo text; Marker A = Claude Sonnet 5.5, Marker B = Gemini 3.5 Flash), `/api/review` (GPT-5.5, called only when the markers disagree), `shared/marking.js` (plain code: agree / disagree / unclear / send-back; confidence under 0.8 or illegible = no mark, never guessed; equal values count, 3/9 = 1/3), Coordinator in `app/orchestrator.js` (two learners at a time, retries, one more try when a marker returns too few answers, Reviewer code check sends a self-contradicting marker back at most twice, then the teacher). Mark screen with ticks per question and per-learner status. Check screen (marking review): both markers' reading, mark and evidence side by side, the Reviewer's read, cropped image of the answer, Mark correct / Mark wrong, undo, then "Confirm marks and delete photos". Formal/informal toggle per task.
- Tested: real end-to-end on the deployed site at 375/768/1024: 7 made-up books snapped, both vendors marked 70 answers, 69 agreed and the scripted wrong answers were marked wrong (e.g. Sipho 8/10, Lerato 9/10 as scripted), Johan's scribbled digit was flagged unclear by BOTH markers with a cropped image and no mark, teacher decision saved ("1 decided by you"). `node --test`: 22 pass.
- Honest observation: in the live runs the two vendors never disagreed on these clear pages, so the Reviewer was not called live. The Reviewer catching a disagreement is therefore proven by the prepared demo run (feature 10) and the unit tests, not by a live disagreement.
- Fixed along the way: Gemini's reasoning used up the token budget so Marker B returned truncated JSON (15 answers falsely "unclear"): set low reasoning effort, 6000 tokens, tolerant JSON repair and one retry. The truncated runs degraded safely (unclear, not guessed).
- Limit: about 60 to 90 seconds for 7 books at two learners at a time.

## 8. Personal homework review + per-learner print — ✅ passing (R7, R15 homework part, R16, R17)
- Done: `shared/homework.js` assembles each learner's sheet in plain code: the questions they got wrong come back first ("Try again"), then 2 practice questions per missed topic from a question bank, and learners who are green on every topic get stretch questions only. The bank is written by the Lesson Writer (`/api/write-bank`, Claude Sonnet 5.5) and every item is re-proved by code; a built-in code bank is the fallback. Homework screen: learner list with Draft/Approved, a preview, memo (teacher only), "Change questions" (edit or empty a line to remove it, answers re-worked by code, approval reset, edits are never overwritten), approve one or all, print one sheet or all approved sheets: one A4 page per learner with the learner's name restored from this phone only at print time.
- Tested: `node --test` 31 pass (targets exactly what was wrong, stretch for learners ahead, none for learners behind, all answers proven). Live on deploy at 1024: after real marking of 7 books, "Write personal homework" -> 7 sheets, Thandi's sheet has her 5 wrong questions + practice and a memo with no blanks, edit saves and re-works, approve, Print this sheet -> `window.print` stub shows exactly one sheet headed "Thandi Mokoena", Approve all + Print approved -> 6 or 7 sheets. 375: the run reached homework generation but the earlier Check steps raced the slower marking (test timing, not an app error).
- Not tested: an actual paper printout (headless cannot print), only the print DOM and print CSS.
- Honest observation: in one 375 live run neither marker flagged Johan's scribbled digit as unclear (so nothing needed a teacher decision), i.e. the "flag, never guess" rule depends on the models and is not guaranteed. The prepared demo run covers the stage.
